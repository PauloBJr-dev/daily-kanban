# Security Policy

We take the security of DailyFlow Kanban seriously. If you have discovered a security vulnerability, please follow the coordinated disclosure process outlined below.

## Supported Versions

| Version  | Supported          |
| :------- | :----------------- |
| Latest   | :white_check_mark: |
| < Latest | :x:                |

## Reporting a Vulnerability

> **Do not report security vulnerabilities through public GitHub issues, discussions, or social channels.**

### Primary Method: GitHub Private Vulnerability Reporting (Recommended)

1. Navigate to the repository's **Security** tab.
2. Click on **Advisories** in the sidebar.
3. Click **Report a vulnerability** to open a private advisory draft.

### Alternative Method: Email

If you cannot use GitHub Advisories, email **contatopborgesj@gmail.com** with details.

### What to Include

- A detailed description of the vulnerability and its potential impact.
- Affected versions, components, or files.
- Step-by-step instructions to reproduce or a minimal Proof of Concept (PoC).
- Any potential mitigations or suggested fixes.

## Response Process

1. **Acknowledgment**: Within **48 hours**.
2. **Triage & Assessment**: Within **5 business days**.
3. **Patch & Disclosure**: Within **30 days** of validation.
